# Retention Failure-Suite and Mitigation Design Lane

Report date: 2026-07-09.
Branch: `coherence-sft`.

This lane is deliberately separate from the live MMLU aggregate/report, Huth,
concept-steering, and ops files. It defines a cheap gate for future
alpha/replay/steering experiments before spending another full MMLU run.

## Current Anchor

`taskvec_a0p25` is a partial mitigation, not a broad fix:

- MMLU merged coverage: 57/57 completed subjects.
- MMLU micro accuracy: `0.622964`.
- Delta vs base: about `-0.070`.
- Delta vs lowrank: about `+0.031`.

That means task-vector addition recovers some multiple-choice retention, but it
still leaves a large residual exam-ranking loss. The failure-suite should
therefore select candidates for the next expensive runs rather than declare the
retention problem solved.

## What The Drops Imply

The induced skill is semantic coherence and human-similarity alignment, not
general benchmark accuracy. Existing artifacts show large gains on generation
coherence and human similarity, while failures concentrate in tasks that need a
sharp boundary:

- Exact factual or formal option ranking: MMLU, ARC, OpenBookQA.
- Lexical sense boundaries: WiC.
- Calibrated rejection of plausible false statements: TruthfulQA.

HellaSwag, WinoGrande, and PIQA are retained better because broad event
plausibility, discourse coherence, and physical affordance semantics overlap
more with the induced semantic geometry. They should stay in the suite as
retention guards so mitigation does not damage skills that are currently mostly
preserved.

## Why TruthfulQA Is Affected

TruthfulQA MC2 is a lure-pressure diagnostic. A plausible false answer can be
semantically close to the question topic, so a semantic-coherence direction can
raise its probability even if the model also raises mass on true answers.

The existing 200-item log-sample readout shows the risk: `taskvec_a0p25` has a
nearly flat diagnostic MC2 score but raises false-answer pressure more than
truthful-answer mass, with false pressure up on `84%` of paired items. The
failure-suite should therefore track false-lure pressure and truth-logodds, not
just aggregate MC2 accuracy.

## Suite Definition

The committed manifest is generated by:

```bash
python src/sft/build_retention_failure_suite_manifest.py
```

Primary artifacts:

- `results/sft_eval/wide_bench/failure_suite/task_slices.csv`
- `results/sft_eval/wide_bench/failure_suite/suite_manifest.json`
- `results/sft_eval/wide_bench/failure_suite/README.md`

The initial suite is about 2.5k bounded items, before any exact item-ID freezing:

| Lane | Slices | Purpose |
| --- | --- | --- |
| MMLU failure slice | moral scenarios, formal logic, medical genetics, nutrition, professional psychology, high school statistics, business ethics | Catch residual MMLU option-ranking failures before full MMLU. |
| Science ranking | ARC-Easy, ARC-Challenge, OpenBookQA | Test fact retrieval plus close distractor ranking. |
| Sense boundary | WiC | Test same-lemma contextual sense decisions. |
| Truthfulness lures | TruthfulQA-MC2 200-item log-sample slice | Track true mass vs false-lure pressure. |
| Retention guards | HellaSwag, WinoGrande, PIQA | Prevent mitigation from damaging mostly preserved skills. |

Exact item IDs should be frozen after the first logit/log-sample pass. Until
then, the manifest uses deterministic limits and item policies. For MMLU, the
post-logit item set should include base-correct/candidate-wrong items, narrow
base-margin items, and random controls within each selected subject. For WiC,
the exact slice should pair by lemma, part of speech, and same/different sense
labels once item metadata is available.

## Metrics Beyond Accuracy

Accuracy is only the first screen. Each candidate should log answer-choice
scores so the suite can compute:

- `correct_choice_margin`: `logp(correct) - max_wrong logp(wrong)`.
- `best_distractor_margin`: `max_wrong logp(wrong) - logp(correct)`.
- `false_lure_pressure`: for TruthfulQA, `logsumexp(false answers)` relative to
  true-answer mass.
- `KL_to_base_logits`: KL from base answer-choice distribution to candidate
  distribution, item by item.
- `semantic_target_retention`: generation coherence and THINGS human R2 must
  remain high enough that a mitigation does not erase the intended skill.

Proposed promotion gates:

- MMLU failure-slice mean delta vs base `>= -0.06` before full MMLU.
- ARC/OpenBookQA mean delta vs base `>= -0.05`, with no task below `-0.08`.
- WiC delta vs base `>= -0.05`, or clear same-lemma margin recovery.
- TruthfulQA `frac_false_pressure_up <= 0.60` on paired log samples.
- HellaSwag, WinoGrande, and PIQA each `>= -0.02` delta vs base.
- Semantic target retention: generation coherence `>= 0.60` and THINGS human
  R2 `>= 0.58`.

## Mitigation Candidates

1. Task-vector alpha sweep.
   Run `0.0`, `0.1`, `0.2`, `0.25`, `0.3`, and `0.5` on the failure-suite
   first. Promote no alpha that improves MMLU while worsening TruthfulQA lure
   pressure or the retention guards.

2. Base-logit KL plus replay.
   Add a small replay/KL objective on multiple-choice prompts from MMLU,
   ARC/OpenBookQA, WiC, and TruthfulQA. Use base answer-choice logits as the
   local calibration target while preserving the semantic SFT target.

3. TruthfulQA lure-focused contrastive examples.
   Add examples that separate true answers from common myths, stereotypes,
   safety folklore, and overgeneralized cultural facts. Optimize true-vs-false
   mass, not aggregate MC2 alone.

4. WiC sense replay.
   Add paired same-lemma sense contrasts and require sense-margin recovery. This
   targets the cleanest observed lexical failure.

5. Adapter routing or merging.
   Use the semantic adapter/task vector for representation extraction and
   semantic-hub or fMRI uses, but downweight or disable it for calibrated
   multiple-choice answering when the suite flags answer-surface damage.

6. Concept-vector steering or ablation gates.
   Treat concept-vector steering as a candidate mitigation only if it passes the
   same margin and lure-pressure gates. Steering gains alone should not count as
   retention recovery without the failure-suite readout.

## Decision Rule

The next full MMLU run should be gated on this suite. A candidate can be called
promising only if it improves the failure slices, keeps TruthfulQA false-lure
pressure controlled, and retains the semantic target gains. Otherwise it should
be reported as representation-useful but not retention-safe.
